# RT2 — attack on the forward plan (read-only pass, 2026-10-02)

Scope: the *path*, not the code and not new ideas. Primary sources quoted; `[C]` = confirmed
from a primary source, `[I]` = inferred/arithmetic. Ordered by damage to the entry.

1. **[C] — §4 states the area constraint 24× too small.** Plan: "one tile = **167 × 108 µm**, roughly **1K cells**" as a *hard constraint*; Jane Street: "**Set the tile size in info.yaml to 6x4**" / "The current maximum area is 6x4 tiles per design" / "An 6x4 allocation is 24 tiles … budget for about 1K logic cells per tile". The one-tile framing is self-imposed, drove the "minimal descriptor", and makes §4's unmeasured-fit the plan's top worry when it is a non-issue at 24 tiles — **delete the 1-tile target, set `tiles: "6x4"`, re-scope the descriptor against ~24K cells.**
2. **[C] — there is no way to get a program into the chip, anywhere in plan, descriptor or pre-reg.** The brief's core ask is "a tiny CPU with an instruction set designed for reading pins, writing pins, counting cycles" and "Your chip should be reprogrammable enough to support new protocols **after fabrication**"; TA-02's frozen state is "`(pc, clock)` and nothing else" with no address/data port, and `ARCH_PREREG_01` already spends all 8 `uio` on protocols ("UART 2 + SPI 4 + I2C 2 = exactly 8"). A judge's first question has no owner — **specify the load path (`ui_in` + handshake into an SRAM-backed table) before any further freeze.**
3. **[C] — RTL is rung 4 of 5 and the brief says do it first.** "**Run synthesis early, check the mapped cell area**, and leave room for clock-tree buffers and routing. Then run the full place-and-route flow and check timing." `src/project.v` is still `tt_um_example` (`uo_out = ui_in + uio_in`) and `git remote -v` is **empty**, so the GDS action — which `ARCH_PREREG_01` itself calls "the trustworthy build path" — has never run once. **Push the repo, set 6x4, run gds + precheck + gl_test on the stub this week; that is the measurement §4 says is missing.**
4. **[C] — every model number hangs on an unsynthesized 50 MHz, so rung 4 can invalidate rungs 1–3.** `CLOCK_PERIOD: 20` is a *template default* in `src/config.json` ("DO NOT EDIT THIS FILE unless you know what you are doing"), the brief mandates no frequency ("too slow at **your chosen** clock frequency"); `T = 434`, the band `[413,458]`, the 64-entry budget and the 5-clk/bit Ethernet duty all re-derive if PnR closes at 25 MHz. **Close timing before spending another rung on model numbers parametrized by it.**
5. **[C] — the frozen descriptor contradicts the pre-registered architecture, and the plan has silently dropped the pre-reg's stated differentiator.** `ARCH_PREREG_01` commits to "a single shared action engine … driven by a deadline-ordered action queue" with per-lane "shift reg, bit counter, divider, next-action timestamp" and prediction A2, "worst-case queue lateness is exactly `(Q-1) x k` cycles and is **provable**"; TA-02's branch audit *proves those registers absent* and kills a bit-counter mutant. The queue, lateness bound and A5 (three protocols concurrently) appear in **no rung** of the plan. **Either retract A2/A5 in writing or put the queue back on the ladder — do not leave two incompatible architectures both "pre-registered".**
6. **[I] — one `pc` cannot run three protocols at once, so A5 is unreachable from this model by construction.** `out` is "a pure function of `pc`" and there is one `pc`; concurrency needs multiple contexts or the dropped queue. The pre-reg sells simultaneity ("all three protocols run **simultaneously** on one engine") as a measured prediction with no path to it. **Decide now: interleaved multi-context table, or withdraw the concurrency claim.**
7. **[C] — the descriptor cannot reach the brief's stretch goals by *kind*, not by one more extension.** "Stretch goals include low-speed USB and 10Mbit Ethernet. Other interesting protocols to consider: JTAG, SWD, PS/2, CAN bus" — USB needs NRZI + bit-stuffing (data-dependent insertion), Ethernet needs Manchester + CRC32, CAN needs stuffing + CRC15; a one-entry-per-bit table with the payload baked in has no shift register, no run-length counter and **no arithmetic at all**. §5's hope that "the 'minimal descriptor' is actually stable" is already false. **Keep the freeze as a TA-02 proof artefact; stop treating it as an architectural commitment.**
8. **[I] — the 64-entry table in flip-flops is ~7–9 tiles, never 1; in SRAM it is ~2.** 64 × (g 16 + out 8 + in_pin 4 + in_pol 1 + next_a 6 + next_b 6) = **2,624 bits** (2,240 bits at a 10-bit `g`); Tiny Tapeout publishes "you can fit about **320 DFFs (40 bytes of memory) in a single tile**" → 8.2 tiles (7.0 at 10-bit `g`), and the brief says "For instruction memory, **SRAM can be more area-efficient than flip-flops**" with IHP single-port macros from 256×8 at ~17.5 kµm² ≈ one 18.0 kµm² tile. **So §4's unpriced item is answerable on paper today and settled for real by one synth run; plan the table as SRAM, not flops.**
9. **[C] — two primary sources disagree on `6x4` and the plan treats neither as authority.** Jane Street: "Set the tile size in info.yaml to 6x4"; the *cmos5l* template's own `info.yaml` (the one this repo is on, branch `cmos5l`): "Valid values: **1x1, 1x2, 2x2, 3x2, 4x2, 6x2 or 8x2**" — 6x4 is **not listed**, so precheck may reject the configuration the competition instructs. `ARCH_PREREG_01` logs this as "UNRESOLVED"; it is resolvable. **Try `6x4` in CI and mail asic-competition@janestreet.com with the two quotes.**
10. **[C] — submission mechanics have no owner and the repo is currently unsubmittable.** `info.yaml` has empty `title`/`author`/`description`, `clock_hz: 0`, `tiles: "1x1"`, `top_module: "tt_um_example"`; `docs/info.md` is untouched template prose ("Explain how your project works"); `src/project.v` header reads "Copyright (c) 2024 Your Name". TT precheck requires all of it green. **Add a submission-checklist rung with these as line items, not a final-week scramble.**
11. **[C] — nothing in the repo evidences the sign-up form, which is the only channel for the submission link and the area decision.** "We'll send updates about the tapeout template, deadlines, as well as **providing the final submission link**"; the possible "8x4 tiles (~30% more area)" goes to "everyone who has signed up". Cost: minutes. Downside: missing the submission route for a Jan 18 2027 deadline. **Fill the form today if not already done.**
12. **[C] — TA-01 §2 option (c)'s stated reason is contradicted by the repo's own evidence; take (a).** (c) argues "the formal models already check phase, so … the Python model was the outlier"; `TA02_RESULTS.md` shows TChecker "checks the **line level** exactly as the Python receiver does" and still lands on 458 — "A level-vs-phase difference cannot produce that". The outlier is caused by the **T+1 period**, not by level-vs-phase, so (c) retires the level check on a false premise and discards it exactly when RTL — which reads levels, not phases — is about to need it. **(a): fix period *and* level check, re-certify TA-01/01b/01c as one unit; the fixpoint re-run is cheap (<1 s at T=434).**
13. **[C] — "structural results untouched" is safe for three theorems and unsafe for the diagnostics that certify them.** Decidability, determinism and totality are argument-level and genuinely independent; but TA-01b's reset diagnostic "max clock `== T`, not `< T` … Off-by-one in the spec's phrasing, not a failure" **is the defect**, and it is load-bearing for BFS termination — a guard that passed because of the defect — and the "13,023 states / 30 states per clock tick" law is a defect-derived number. **Re-derive both diagnostics under the fix; do not re-word them.**
14. **[C] — the plan bets on the wrong half of the judging criterion.** "We're particularly interested in projects with **unique functionality**, as well as those that demonstrate novel approaches to design and verification methodologies" — functionality is named first, and `ARCH_PREREG_01`'s own field sweep says competitors already run "formal k-induction, three-corner SDF, mutation testing" and "an entry whose only distinction is 'we have a good testbench' is not distinguished". The five rungs are five verification rungs. **Pair each remaining rung with a functionality deliverable, or the formal work carries an entry that does nothing.**
15. **[C] — the FPGA step is in the brief, owed in the record, and absent from the plan.** "If you have access to an FPGA, consider using it to test your RTL before the ASIC flow"; `TA01bc_RESULTS.md` and `TA02_RESULTS.md` both list "Still owed: a real receiver at the FPGA stage"; `.github/workflows/fpga.yaml` exists unused; the five rungs never mention it. **Make it an explicit rung between RTL and fab — it is also the only place a *real* receiver tests finding 2's level-check hazard.**
16. **[C] — rung 4 "the RTL refinement probe" names a question and no mechanism.** The model is Python and the RTL will be Verilog; `test/test.py` is the stock stub (100 kHz clock, `assert dut.uo_out.value == 50`), `gl_test` is an existing CI job nobody has planned for, and there is no constrained-random, no SDF corners, no mutation on the RTL. **Name the bridge now: cocotb dumps the DUT waveform into the *same* sigrok decoders and `cmp`s against the interpreter's bytes, run at RTL and gate level in CI.**
17. **[I] — rung order inside the model layer is backwards: the data source should precede TA-03.** The plan itself says the extension "adds state the branch-point audit currently proves absent"; proving SPI determinism/totality/band over a descriptor you are about to extend buys a proof you then have to re-run. **Price and land the data source first, then do TA-03 once.**
18. **[C] — tri-state is deferred to rung 3 although the pre-reg says it blocks everything.** F5: "if open-drain I2C cannot be expressed through `uio_oe` as modelled → the pin abstraction is wrong and **must be fixed before any protocol work continues**"; the plan puts it third. A pin-abstraction failure found after TA-03 invalidates TA-03's `out` field. **Settle `uio_oe` semantics in the same pass as the RTL stub — it is a 20-line test, not a rung.**
19. **[C] — stop spending attack budget on §5's first assumption; the brief settles it.** "The goal **isn't** to put a UART block, an SPI block, and an I2C block on one die and call it done … look at the PIO state machines on the RP2040 or the PRU cores on TI's Sitara parts" — table-driven is the asked-for shape, and "that one tile is the target" is likewise settled by #1. **Two of §5's five open assumptions are closed by the primary source; strike them and re-aim at #2, #5, #7.**
20. **[C] — the entry is solo against an explicit team recommendation, and the plan has no capacity line.** "This is a much bigger project than the puzzle, so we **strongly recommend working in teams**"; six rungs of formal work plus RTL, FPGA, PnR, precheck and docs sit with one person, and zero of the silicon-side work has started. **Either recruit, or cut the ladder to: RTL + 3 protocols + one formal result that the RTL actually satisfies.**
